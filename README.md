# DAS-VTX — Vehicle Tracking and Cross-Correlation for DAS Surface Waves

DAS-VTX is a Python workflow for retrieving and interpreting surface-wave energy generated by moving vehicles and recorded with Distributed Acoustic Sensing (DAS). The framework was developed for road-traffic and railway applications and organizes the processing into three stages that can be run independently or sequentially:

1. **moving-source tracking** in DAS space-time data;
2. **trajectory-guided cross-correlation and Virtual Shot Gather (VSG) stacking**; and
3. **frequency-phase-velocity dispersion imaging and optional aperture-stability masking**.

## Scientific workflow

### 1. Tracking and surface-wave window selection
Raw DAS data are temporally decimated for the tracking stage. The configured preprocessing chain can include spatial interpolation, apparent-velocity filtering in the f-k domain, band-pass filtering, Savitzky-Golay smoothing, velocity-aligned spatial averaging, nonlinear amplitude weighting, and spatial oversampling.
Candidate source times are detected from peaks close to the beginning of the tracking section. The trajectories are propagated along the fiber with the existing Kalman-filter formulation and screened using the configured missing-data, average-speed, curve-break, and speed-fluctuation criteria.
For every accepted trajectory, DAS-VTX extracts a raw-data surface-wave window centered in time on the source crossing of the configured pivot. 

### 2. Trajectory-guided VSG construction and stacking
Each selected surface-wave window is tapered and can be band-pass filtered and spectrally whitened. DAS-VTX then moves the virtual-source position along the tracked vehicle trajectory and cross-correlates the corresponding time windows with neighboring channels.
The VSG implementation in `VSG_class.py` is the trajectory-guided method used by DAS-VTX. Individual VSGs are recursively stacked. `calculate_SNR()` records a diagnostic SNR after each successful addition to the stack. 

### 3. Dispersion interpretation
The stacked VSG can first be restricted to forward/backward offsets and causal/acausal lags. Optional coherence enhancement evaluates local semblance over the configured slowness grid. The interpolated coherence field is squared and multiplied by the VSG, preserving the behavior of the reference implementation. The dispersion image is calculated by transforming the available propagation quadrants to the f-k domain, and sampling the result along k = f / v for the configured frequency and phase-velocity grids.
When `disp_masking = True`, DAS-VTX recomputes the dispersion image after progressively reducing the maximum retained VSG offset. The normalized accumulation forms an aperture-stability mask: dispersion energy that is repeatedly recovered as the usable aperture changes receives a larger weight.
The final full-aperture dispersion image is retained, and the mask and masked dispersion image are saved separately.

## Configuration

The supplied repository contains two experiment-specific configurations:
- `config_cars.py` for road-vehicle data;
- `config_trains.py` for railway data.

In `main.py`, before the processing modules are imported, the selected configuration file is copied to `config.py`.
The default is the train configuration. Select another configuration without editing the source by setting `DAS_VTX_CONFIG`:

```bash
DAS_VTX_CONFIG=cars python3 main.py
```

or

```bash
DAS_VTX_CONFIG=trains ./launch_main.sh
```

The three main execution flags are:

| Parameter | Purpose |
|---|---|
| `RUN_TRACKING` | detect/track moving sources and save surface-wave windows |
| `RUN_XCORR` | convert detections to VSGs and stack them |
| `RUN_INTERPRETATION` | calculate dispersion products and diagnostic figures |

When interpretation is run without cross-correlation, `stack_files_list` can point to a single `.npz` stack, a list/tuple of stacks, or a directory containing stack files.

### Important configuration conventions

- `tracking_sections` contains `(start, pivot, end)` fiber distances in meters; the pivot is used to center surface-wave windows on the tracked source crossing.
- `xcorr_sections` contains `(start, end)` fiber distances in meters; the current VSG method sweeps the virtual-source position along the trajectory and therefore does not use a fixed cross-correlation pivot.
- `start_hour <= hour < end_hour` defines the daily tracking interval.
- `dx` is the inter-channel spacing in meters.
- `wlen_sw` is the total extracted surface-wave window after the taper margin is added.
- `xcorr_parameters[*]['wlen']` is the cross-correlation window length in seconds.
- `delta_t` shifts each correlation interval relative to the interpolated source-passage time at the current virtual-source position.
- `time_window_to_xcorr` controls the trajectory-centered data interval from which windowed correlations are formed.
- `slw_list` contains trial slownesses in s/m for coherence enhancement.
- `xwin` and `twin` control the local coherence windows.
- `max_cut_dist`, `min_cut_dist`, and `step_factor * dx` control aperture reduction during dispersion masking.

## Data-array conventions

Throughout the implementation, DAS and VSG matrices use the convention:

```text
array.shape == (space, time)
```

For a VSG:

- `x_axis` is the inter-channel-distance axis [m];
- `t_axis` is the correlation-lag axis [s];
- `XCF_out` is the correlation-amplitude matrix.

For a dispersion object:

- `freqs` is frequency [Hz];
- `vels` is phase velocity [m/s];
- `fv_map.shape == (len(vels), len(freqs))`.

## Input adaptation

`func_data_imports.py` is intentionally isolated from the rest of the workflow. The supplied implementation uses Febus Optics A1R output files. For another interrogator or file convention, adapt this module while preserving the returned interface:

```python
strain_rate, distance, time, data_attributes = data_matrix_import(...)
```

The returned strain-rate matrix must be shaped `(n_channels, n_samples)`.

## Outputs

All processing products are written below `PROCESSED_DIR`.

```text
PROCESSED_DIR/
├── detects/
│   └── YYYYMMDD/<raw-file-stem>/...npy
├── VSGs/
│   └── STACKs/...npz
├── DISPs/
│   └── Disp_<stack-name>.npz
├── FIG/
│   ├── Stack/
│   ├── SNR/
│   └── Disp/<stack-name>/...
└── YYYYMMDD_HHMMSS.log
```

### Detection files

Each `.npy` file stores a pickled `SurfaceWaveWindow` containing the raw extracted DAS window, its axes, and the tracked trajectory in both index and physical-coordinate representations.

### VSG stack files

Each stack archive contains:

- `parameters`: cross-correlation parameters;
- `SNR`: SNR evolution as the stack grows;
- `vsg_times`: timestamps of successfully stacked detections;
- `stack`: the stacked `VirtualShotGather` object.

### Dispersion files

Every dispersion archive contains:

- `parameters`;
- `disp`: full-aperture dispersion image;
- `freqs` and `vels`;
- `vsg_times`.
